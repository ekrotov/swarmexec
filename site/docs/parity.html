CLI · TUI · MCP_

Which interface does what — and why some things live in the TUI alone.

swarmexec has three faces: the CLI for scripts and one-off commands, the TUI (swarmexec ui) for looking around and changing things interactively, and the MCP server (swarmexec mcp) that lets an AI assistant read the services you opt in. This table puts them side by side.

The rule behind it: whatever the TUI changes has a CLI twin, or is listed here as TUI-only with its reason. The MCP server is read-only on purpose, with one exception (exec_run, off unless a service's labels allow it), so a write action is never a gap in the MCP column. The CLI reference lists every command and flag.

A cell names the command, key or tool. — means the interface does not offer it. Rows marked TUI only are deliberate; the reason is under the capability.

Changing a service

These are the editors behind i → a on a service (edit a service). They are TUI-only on purpose: each is an interactive, staged edit of one live service. In a script the declarative way is the stack file — stack diff, then stack deploy — and every one of them is also a docker service update flag against the manager, which swarmexec does not need to repeat.
