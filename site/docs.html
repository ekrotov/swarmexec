Operating the client — commands, flags, config & the TUI.

swarmexec gives you docker exec -it, logs, port-forwarding and volume management against any container in a Docker Swarm, from one terminal. A small per-node agent (a global Swarm service) does the work on its node; the client asks the Swarm manager which node runs your target, then connects straight to that node's agent over mTLS. These pages document the client; for whole workflows — debugging a crash, rotating a secret, gating a deploy — see the recipes.

Getting started

  • Install & quick start — Install the swarmexec client with the script, Homebrew, Scoop or a binary, check the Docker Engine requirements, add shell completion, and run your first exec in a Docker Swarm.

Commands

  • exec into any Swarm container — Open a shell or run a command in any container of a Docker Swarm, on whatever node it runs: target selectors (service, service.slot, task id, container id), swarmexec ps and the exec flags.
  • Logs of services and stacks — Stream logs of a service, several services or a whole Docker Swarm stack: follow across container replacement, the last container of a crash-looping service, log-format parsing, --min-level and --grep.
  • port-forward into the Swarm — Forward a local TCP port to a port inside a container anywhere in a Docker Swarm, without publishing it: syntax, flags, loopback binding and why a service target means one task.
  • Stack export, diff & wait — Export a deployed Docker Swarm stack as a file, diff a stack file against what is deployed by content rather than text, with exit codes for CI, and wait until a deploy has really converged.
  • Security scan & report — Check a stack file before it is deployed and stop on findings with swarmexec stack deploy --check, and write a Markdown security report of the whole Docker Swarm cluster.
  • Rotate a secret, keep its name — Give a Docker Swarm secret that services use new content without renaming it to _v2: how swarmexec secret rotate works, resuming an interrupted rotation, and its flags.
  • Volumes & prune schedule — List volumes on every Docker Swarm node with the services that use them, remove one on the node that holds it, and set the cluster-wide prune schedule the agents run.
  • MCP server for AI assistants — swarmexec mcp lets Claude Code and other MCP clients read status, logs and stack diffs of the Docker Swarm services you opt in by label — read-only, with labels hidden from the assistant.

How it works

Two binaries, one wire protocol:

  • agent — runs as a global Swarm service (one task per node), mounts that node's Docker socket, and exposes a narrow gRPC API that proxies exec / logs / port-forward into containers on its own node. You deploy it once with swarmexec init.
  • client (this CLI) — runs on your workstation. It talks to the Swarm manager API to resolve which node runs your target and the container id, then dials that node's agent directly on port 9443. There is no agent-to-agent mesh.
operator terminal ──gRPC/mTLS──> agent(nodeN) ──docker.sock──> container │ └── Docker manager API (resolve node + container id)

The manager connection uses your Docker CLI context (so it honours --context, ssh:// bastions, mTLS, etc.). The agent connection is authenticated with mutual TLS, or with a shared secret against a self-signed agent — see Authentication.
